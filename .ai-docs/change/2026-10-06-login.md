# ログイン機能を追加

ID: I-014

## 背景
本番に認証がなく、URL を知っていれば誰でも作業記録の閲覧・タイマー操作・Hook URL の書き換えができた。

## 判断
- Basic 認証ではなく、ID・パスワードのログインフォーム（ユーザーの希望）。アカウントが1件もないときだけ初回登録を受け付ける。
- ローカルはログイン不要（ユーザーの希望）。Host ヘッダーは偽装できるので、REMOTE_ADDR がループバックであることも条件にした。
- 既存の `api/hook.php` は timer.php が自分自身へ HTTP で呼ぶ作りで、ログイン必須にすると Cookie なしの内部呼び出しが失敗する。
  そこで Hook 送信を `includes/hook.php` の `dispatch_hook()` にまとめ、timer.php・cron_check.php・settings.php の3つの重複実装を置き換えて、`api/hook.php` は削除した。
  timer.php からの送信は従来の内部呼び出しと同じく3秒で打ち切る（以前は内部呼び出しが3秒で切れても hook.php 側は最大5秒まで送り続けていた。3秒以上かかる送信先は今後失敗扱いになる）。
- セッションはサーバー共通の置き場だと他アプリの GC で消されやすいため、`data/php_sessions/` に専用で置き、30日有効にした。
- 総当たり対策として、5回連続失敗で15分ロック。存在しない ID でもパスワード検証を行い、応答時間で ID の有無が分からないようにした。
- cron_check.php は CLI からは認証なしで動く。HTTP で叩く場合はログインが必要（これまで誰でも自動完了を起動できた）。

## 確認
LAN の IP 経由（ローカル扱いにならない経路）で、未ログイン時の転送・API 401、登録・CSRF 不一致・確認パスワード不一致、
ログイン・ログアウト、2件目の登録拒否、5回失敗でのロック、`data/auth.json` が HTTP で 404 になることを確認した。
