# T-014 休みの日・稼働日を日付単位で登録できるようにする

ID: T-014
日付: 2026-10-12
バージョン: 1.5.0

## 判断・意図
- 曜日の既定（木金休み）に対する日付ごとの例外を `data/calendar.json` に持つ。値は `off` / `work` だけで、「既定に戻す」はキーを消す（`default` は保存せず操作名にだけ使う）。日付の値が曜日の既定より優先する。git 管理外（`.gitignore`）。
- 画面は専用の `calendar.php`（ヘッダーのナビ「カレンダー」）にした。統計のタブにしなかったのは、統計は読み取り専用の集計で、カレンダーは設定に近い書き込み操作だから。トップの heatmap カレンダーとは別物。
- 保存は新しいエンドポイントを増やさず `api/timer.php` の `set_day_type`（slot 不要の非スロット系。既存のログイン認証・JSON POST の流儀）にした。Claude 用 API の `set_day_type` と同じ `koma_calendar_set()` を呼ぶ。
- 週の状況は、その週の日曜〜土曜の各日を「日付の例外 → 曜日の既定」で判定する（`koma_week_status()`）。休みの判定は PHP だけに置き、JS は PHP が渡す `workDays` / `perDay` / `elapsedWorkDays` / `remainWorkDays` / `todayOff` を使う。以前 JS が持っていた `offDays.includes(dow)` の判定をやめたので、PHP と JS で休みの規則がずれる余地がなくなった。差・必要ペースの規則（PHP の `koma_week_progress()` と JS の `weekStatus()`）は T-013 のまま、両方にある。
- 稼働日が0の週は1日の目標を0とし、ゼロ除算しない。パネルは主表示（今週 X / 目標・あと Y）に加えて「今週は休み」と注記を出し、遅れ/進みと必要ペースは出さない。休みの日の作業は従来どおり目標累計に足さず実績にだけ入る（API の `diff` は実績そのもの＝進み）。
- 次週以降の例外は、今週の日付しか見ないので今週の表示に影響しない。過去の週の日付の例外は編集もそのまま使われる（過去の日付も登録は可）。
- 見た目: 稼働（既定）= 無地、休み（曜日の既定）= 灰色・点線、休み（日付で登録）= 赤、稼働（日付で登録）= 緑。色だけに頼らずラベル（休(曜日) / 休み / 稼働）も付けた。ダーク/ライトの変数（`--red-bg` など）で両対応。
- 登録件数は5000件を上限にした（ファイルが際限なく増えないため。実用上到達しない）。
