# 変更ログ：翌日コマ数リセット・前日未完了コマ時間表示修正

> 2026-06-22 #I-009 #I-010

---

## fix #I-009: 翌日になってもコマ数が6にリセットされない

### 原因

`addKoma()` が `set_slot_count` API に `date` を渡していなかった。
API 側は受信 `date` がない場合は `today_str()`（サーバーの現在日付）を使う。

深夜0時をまたいでコマを追加した場合、ユーザーが見ているページはまだ「前日」だが
サーバーは「今日」に切り替わっており、`set_slot_count(8)` が翌日のセッションファイルに書き込まれる。
翌日リロードすると翌日のセッションに `slot_count=8` が入っているため 8 コマ表示される。

### 修正

**`assets/js/timer.js`**
- `addKoma()` 内で `apiCall('set_slot_count', { count: next, date: CFG.today })` に変更
- `CFG.today` = ページロード時の PHP 日付なので深夜またぎでも正しい日付がサーバーに届く

**`api/timer.php`**
- `set_slot_count` で `$target = $req_date ?? today_str()` を使うよう変更
- `$req_date` は `req['date']` から YYYY-MM-DD 形式のみ受け付けてパース済み

## fix #I-010: 前日未完了コマの時間が正しく表示されない

### 原因

**原因1（PHP側）**: `index.php` の `$prevIncomplete` 構築では `total_seconds` を再計算していなかった。
JSONに保存された stale な値（コマ開始時点 = 0、またはその後保存された古い値）がそのままJSに渡る。

**原因2（JS側）**: `renderPrevKoma` は `liveElapsed(k)` を常に使っていた。
実行中（running）のコマはセグメントが開放のまま（`end`なし）なので `Date.now()` を end として使い、
前日10:00開始なら「今 = 翌日10:30」として25時間超のelapsedになる。

### 修正

**`index.php`**
- `prevIncomplete` を構築するループ内で `total_seconds` を PHP でインライン再計算
- 実行中セグメント（`end`なし）は `new DateTime('now', $tz2)` を end として計算
- JSONの stale な値を上書きして正確な値をJSに渡す

**`assets/js/timer.js`** — `renderPrevKoma()`
- ステータスごとに elapsed の計算を分岐:
  - `done` (completed等): `k.total_seconds`（固定値）
  - `running` / `overtime`: `k.total_seconds`（PHP計算の初期値）＋ ページロード後の経過秒数
    (`sinceLoad = Math.floor((Date.now() + _clockOffset - CFG.serverNow) / 1000)`)
  - `paused`: `liveElapsed(k)`（クローズ済みセグメントの合計 = 正確）
- 重複していた `const isRunning` / `const done` 宣言を削除し `isRunningPrev` / `donePrev` に統一

### 動作

- 前日実行中コマ（running）: PHPが10:30開始→翌日09:00時点の計算値（22.5時間）をベースに、
  ページロード後の経過秒数が加算されて正確にカウントアップされる
- 前日一時停止コマ（paused）: `liveElapsed` がクローズ済みセグメントを合算して正確な値を表示
- 完了コマ: `total_seconds` を固定表示

### 変更ファイル

- `index.php`: `prevIncomplete` 構築時に `total_seconds` を再計算
- `assets/js/timer.js`: `renderPrevKoma` の elapsed 計算を分岐、変数重複を解消
- `api/timer.php`: `set_slot_count` に `date` パラメータ対応
