# スロットリセットバグ修正

> 日付: 2026-04-19

## 問題

前日に動的追加（`addKoma()`）したスロット 7・8 が翌日もグリッドに残る。

### 原因

1. `update_meta` アクション（名前入力のオートセーブ）が `ensure_koma()` を呼ぶ
2. `ensure_koma()` は koma が存在しない場合 `status: idle`・`segments: []` のレコードを JSON に作成して保存する
3. 翌日 `index.php` をロードすると `$maxExistingSlot = max(array_keys($komaMap))` が idle koma の id=7 を拾い `$renderSlotCount = 7` になる
4. 以降毎日「前日の idle koma が最大スロット」として固定化される

## 修正内容

### `index.php`（`$maxExistingSlot` 計算ロジック変更）

**変更前:**
```php
$maxExistingSlot = empty($komaMap) ? 0 : max(array_keys($komaMap));
```

**変更後:**
```php
// idle かつ segments が空の koma（phantom）はカウントしない
$maxExistingSlot = 0;
foreach ($komaMap as $slotId => $k) {
    if (!($k['status'] === 'idle' && empty($k['segments']))) {
        $maxExistingSlot = max($maxExistingSlot, (int)$slotId);
    }
}
```

### データ修正

`data/sessions/2026/04-19/data.json` から phantom の `id:7 / idle` koma を削除。

## 影響範囲

- 翌日ページロード時のスロット数が正しく `koma_count`（デフォルト 6）にリセットされる
- 実際に開始済み（segments あり）の高スロット番号 koma は引き続き表示される
- `update_meta` の挙動自体は変更なし（idle koma の作成は維持・表示に影響しなくなった）
