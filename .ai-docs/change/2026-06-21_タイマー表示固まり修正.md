# 変更ログ：タイマー表示が進まない・ズレる問題の修正

> 2026-06-21 #I-008

---

## fix #I-008: ブラウザ表示のタイマーが進まない・時間がズレる

### 原因

`liveElapsed(k)` 内で、実行中セグメントの経過時間を算出するために
PHPサーバー時刻のISO文字列（`seg.start`）と `Date.now()`（ブラウザ時刻）を直接比較していた。

サーバーとブラウザの時計にズレがある場合（サーバーが数秒進んでいるなど）、
`end - start` が負になる → `Math.max(0, ...)` が0を返す → elapsed = 0のまま固まる
という挙動が発生していた。

また、`seg.start` の日付文字列が無効な場合（`NaN`）への対処がなく、
`total += NaN` でelapsedが`NaN`になるリスクもあった。

### 修正

**`index.php`**

`KOMA_CONFIG` にサーバー現在時刻（ミリ秒）を追加:

```php
serverNow: <?= (new DateTime('now', new DateTimeZone('Asia/Tokyo')))->getTimestamp() * 1000 ?>,
```

**`assets/js/timer.js`**

ページロード時にサーバー／ブラウザ間のクロックオフセットを算出し、
`liveElapsed` 内で `Date.now()` に加算してサーバー基準の時刻に補正:

```js
const _clockOffset = (CFG.serverNow || 0) - Date.now();

function liveElapsed(k) {
    const now = Date.now() + _clockOffset; // サーバー時刻基準に補正
    // ...
    if (isNaN(start)) continue;           // 無効日付を安全にスキップ
    const diff = isNaN(end) ? 0 : Math.floor((end - start) / 1000);
    if (diff > 0) total += diff;
}
```

### 動作

- サーバーが5秒進んでいても `_clockOffset = +5000ms` で補正され、elapsed が正しく算出される
- ページロード直後から正確なカウントが表示される
- `NaN` な日付文字列があってもスキップして0加算（サイレントフェイル）

### 変更ファイル

- `index.php`: `KOMA_CONFIG` に `serverNow` を追加
- `assets/js/timer.js`: `_clockOffset` 算出＋`liveElapsed` に補正適用・NaN安全処理追加
