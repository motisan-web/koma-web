# 変更ログ：動的追加コマのリロード消失バグ修正 (#I-007)

> 2026-06-21

---

## fix #I-007: コマ追加後リロードで消える＆追加時にデータが入る

### 原因

**リロードで消える側:**
`index.php` の `$maxExistingSlot` 計算は `idle` かつ `segments` が空のコマを除外している（前日の phantom koma 対策）。
追加ボタンで追加しただけで未操作のコマはまさにこの条件に該当するため、リロード後に `$renderSlotCount` が `koma_count`（デフォルト6）に戻ってしまっていた。

**追加時にデータが入る側:**
`initFromState` は session 内の全コマを `komaState` に読み込む。
slot 7 以降がDOMに存在しなくても `komaState[7]` にはデータが入っている。
「追加」ボタンでカードを生成して `renderKoma(7)` を呼ぶと、既存データが即反映された状態のカードが出てくる。

両症状の根本は「追加したスロット数がサーバーに保存されていない」こと。

### 修正

**セッションに `slot_count` フィールドを追加**
- ユーザーがコマを追加するたびに `session['slot_count']` をサーバーへ保存する
- リロード時はこの値を参照してレンダリングコマ数を決める

**変更ファイル:**

`api/timer.php`
- `set_slot_count` アクションを slot バリデーション前（non-slot actions ブロック）に追加
  - `count = max(リクエスト値, デフォルト koma_count)` で下限を設け、20 で上限
  - 今日のセッションに `slot_count` を書き込んで保存

`index.php`
- `$renderSlotCount` の計算に `(int)($session['slot_count'] ?? 0)` を追加

```php
// 変更後
$renderSlotCount = max($komaCount, (int)($session['slot_count'] ?? 0), $maxExistingSlot);
```

`assets/js/timer.js`
- `addKoma()` 内でカード生成後に `apiCall('set_slot_count', { count: next })` を呼び出し（fire-and-forget）

### 動作

- コマを8個に増やした状態でリロード → 8個表示される
- 追加ボタンを押すと9個目の新規カードが出る（既存データが入った7・8番は既にページロード時から表示済みのため混乱なし）
