# T-013 Claude がコマのデータを取得・更新できる API とスキル

ID: T-013
日付: 2026-10-12
バージョン: 1.4.0

## 判断・意図
- phone-image-share と同じ方式（Bearer トークン + スキル + `~/.claude/*.env`）に合わせた。ログイン・CSRF とは独立させるため、`api/claude.php` は `auth_require_api()` を使わずトークンだけで認証する。
- トークンは SHA-256 のハッシュだけを `data/claude_token.json` に保存する。トークンは256ビットの乱数なので、パスワード用の遅いハッシュ（`password_hash`）は不要と判断した。有効なトークンは1つだけ（再発行＝失効）。複数トークンや用途別スコープは今は持たない。
- 更新範囲は `name` / `project_id` / `silent` の3つに絞り、ほかのキーが付いていたら無視ではなく 400 にした（「できないこと」を API 側でも明示するため）。新規作成も許さない（404）。
- 静音タグは UI（`initSilentSelect()`）が作業内容の最後に ` @タグ` を足す方式なので、API も同じ形に合わせ、付け替え時は既存の静音タグを外してから足す。200文字を超える場合は本文側を切ってタグを残す。
- `week_status` の差・必要ペースは JS にしかなかったので、PHP に `koma_week_progress()` を足した（JS の `weekStatus()` と同じ規則）。トップの値と同じ数字を返すため。変えるときは両方直す。
- 読み取りは書き込みを伴わない（`koma_auto_close_stale()` を呼ばない・セッションファイルを作らない）。
- 設定画面は Claude 連携の card を保存フォームの下に独立したフォームで置いた。CSRF 確認のため `auth_start_session()` を出力の前に呼ぶ（ローカルでは `auth_require_page()` がセッションを開始しないため）。
- `.htaccess` に `SetEnvIf Authorization` を足した（Xserver の FastCGI で `Authorization` が落ちる対策。本番では未確認）。

## 影響
- 新規: `api/claude.php`、`includes/claude_token.php`、`.ai-docs/specs/claude-api.md`、`~/.claude/skills/koma-web/SKILL.md`。
- 変更: `settings.php`、`includes/koma_stats.php`（`koma_set_silent_tag()` / `koma_week_progress()`）、`.gitignore`（`data/claude_token.json`）、`.htaccess`。
- 本番で使うには、設定画面でトークンを発行し、`~/.claude/koma-web.env` に `KOMA_BASE` / `KOMA_TOKEN` を書く（ユーザーが行う）。
